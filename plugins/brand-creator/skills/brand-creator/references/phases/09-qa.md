## Goal

Every rule that can be a script is one, every gate is proven by a deliberate break, and `brand-creator check` exits 0
for every artefact that exists. What no script can decide is named as judgement, with who decided it and when.

## Inputs

- The reports in `assets/_checks/*.json`, `assets/manifest.json`, `history/MANIFEST.sha256`, `tools/inputs.json`.
- `qa/rules.json` (the owner's thresholds and size bands; the proposals in `scripts/lib/qa_rules.py` apply until set).
- `tokens/exceptions.json`, `qa/idempotence.json` (accepted misses and byte differences, each with a reason).

## Outputs and paths

| Output | Path |
|---|---|
| One report per tool | `assets/_checks/<tool>.json` (`status`: pass, fail or not-verified) |
| The gate over all of them | `assets/_checks/check.json` |
| Evidence-tagged rules | BRAND-STATE.md Notes and the book: each rule line carries one tag (below) |

## Taxonomy

Every check result is one of three kinds:

| Kind | Meaning | Exit | What you do |
|---|---|---|---|
| **gate** | a script measured it against a rule and it can fail | 1 on fail; 3 when it could not run | fix the cause, or record an exception with a reason the owner accepts |
| **warning** | a script found something the owner must know, but it does not block | 0 | list it in "Still open" until the owner answers |
| **judgement** | no script can decide it; a person looked | none | write who decided, what and when |

A check that could not run is "not verified" (exit 3), never a pass and never a warning. Every reviewer claim maps to
a command the lead can rerun, or it is a judgement item and is called one.

**Evidence tags.** Every rule, number and quality claim in BRAND-STATE, the book and the reply carries one:

- `[measured]`: a script measured it in this project. Give the report and the value, for example "[measured] accent
  holds a 4 x 4 px square at 16 px (assets/_checks/downscale/<master>-<hash>.json)".
- `[judgement]`: a person's read. Give who and when, for example "[judgement] the mark reads calm at 16 px (owner,
  <date>)".
- `[practice]`: a convention or heuristic the owner adopted, not a standard. Give its origin, for example "[practice]
  colour-vision distance ΔE2000 at least 10 (heuristic proposal, adopted at G4)". A threshold from a standard names the
  standard ("WCAG 2.2 AA 4.5:1"), and the value checked against it is `[measured]`.

**Every gate is proven by a deliberate break.** A gate counts only when a test breaks an input and the gate then fails.
`(m)` marks a mutation test: a scratch copy changed with `mutate()` or `mutate_json()` (`mutateText()` in the node tests),
which assert that the change applied (a mutation that did not apply proves nothing). `(f)` marks a purpose-built failing input (a fixture page, a
constructed image or a bad config). A new check without a test in the table below is a warning, not a gate. A test
keeps this table honest: every cited test must exist, and every `(m)` test must call one of those helpers.

## Warnings

These print in the reports and in `check`, and do not block. Carry each one in "Still open" until the owner answers.

- A platform-spec row with status U or R, or past its date, used by a pack (every emitter and `check`; `specs-due` lists
  them).
- An exception applied (`tokens/exceptions.json`): the miss stays visible with its reason. An exception that matches
  nothing, or a pair that now passes anyway.
- `downscale --previous`: a smaller solid square than before at a rule size ("REGRESSION").
- `fontcheck`: a missing typographic extra; more than two font families.
- A dark set recoloured from the light drawing because no `-dark.svg` exists.
- An idempotence allowlist entry that matches no difference.
- Text fields left empty because FACTS.md has no row (AppStream stub, store frames); the Pillow `.icns` without a
  16 px entry.
- APCA Lc: an advisory column, never a pass or a fail.

## Judgement items

No script decides these. Each one is written as "[judgement] <what> (<who>, <date>)":

- Taste: the pick, the refinement, whether today's mark still wins.
- Distinctiveness against the five-competitor lineup, and the signature move against siblings (family-check measures
  tile shares, not character).
- Kerning set by eye after `outline-glyphs`, and a trace's fidelity to the original.
- Whether an accepted exception is acceptable: the owner's call, with the reason recorded.
- The motion rules no script measures: touch never blocks scrolling, no audio before a gesture, key listening only
  in view, animated text readable by assistive technology, the script budget.
- Print, beyond what `print-check` reads: PDF/X conformance, ink limits, trapping, spot colours (never produced: a spot is a name plus a Lab target
  in LAUNCH, and "hex equals spot" is never written), the paper stock and the printer's own bleed. These are the printer's preflight and
  contract proof, an owner step; no file of ours is "print-ready" or "conforms".
- A reviewer's claim that maps to no command: it is judgement and is labelled so, or it is turned into a command.

## Gate

`check` exits 0 before G5, and before any hand-off that calls a pack done. Exit 3 is reported as "not verified: <why>"
with the fix it names. Never round it up to a pass. A test run that skipped platform tests prints a NOT VERIFIED
banner, and `check` reports those areas as not verified.

## Pitfalls

- Reporting a check that did not run (exit 3, a skipped test) as passed.
- A new gate with no deliberate-break test, or a mutation that never applied.
- A quality claim with no tag: "looks crisp at 16 px" instead of a measured number or a named judgement.
- Lowering a threshold yourself to make a gate pass. A threshold changes only as the owner's recorded decision (G4 or
  DECISIONS.md, with the measured value it was set against); a single accepted miss is an exception with a reason.
- Comparing downscale numbers from different methods (`sips` against resvg or Pillow).
- Treating a warning as noise: unverified spec rows and applied exceptions belong in "Still open".

## Enforcement

- Script: every command in the table writes its report under the contract (`scripts/CONTRACT.md`, Reports and Exit
  codes), and `check` re-reads them and recomputes their input hashes.
- Tests: the cited tests run in `tests/run-all.sh`; `test_skills.py` fails when a test cited here does not exist, when a
  test marked `(m)` does not mutate, or when a check command of the entry point is missing from the table.
- Prose: this file, the evidence tags and the response template ("My honest read" uses measured numbers).
